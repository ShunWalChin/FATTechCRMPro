# Acessos administrativos e integridade de leads — 12/09/2026

## Comportamento desta versão

O CRM distingue Root, Super Admin, Admin, Integrante e Somente leitura. Todos os
perfis continuam restritos à organização da sessão. Root é um perfil da aplicação,
sem privilégios de sistema operacional ou bypass do isolamento de dados.

| Perfil | Administração de equipe |
|---|---|
| Root | Gerencia os perfis da organização; o último Root ativo é protegido |
| Super Admin | Gerencia Admin, Integrante e Somente leitura |
| Admin | Gerencia Integrante e Somente leitura |
| Integrante / Somente leitura | Não concedem permissões nem redefinem senhas de outros usuários |

O owner legado mantém a equivalência de Super Admin. Usuários não alteram o próprio
perfil por autoatendimento. A API verifica ator, alvo e perfil pretendido sob bloqueio
transacional. Mudança de perfil, desativação e reset administrativo revogam sessões
e chaves de API do alvo. Chaves de superiores não ficam disponíveis aos subordinados.

A página Equipe usa as capacidades retornadas pela API e permite criar, editar,
ativar/desativar e redefinir senha dos acessos autorizados. Configurações oferece
troca de senha pessoal e encerramento de outras sessões. A troca pessoal mantém a
sessão atual e encerra as demais. Formulários de senha usam POST.

O provisionador `python -m fattech.provision_access` recebe descritores JSON pelo
stdin e gera senhas aleatórias, armazenadas no banco somente como hash Argon2.
A saída contém credenciais e deve ser redirecionada para arquivo privado 0600.
Reexecuções não trocam senhas existentes; conflitos de organização/perfil abortam
a transação. Nenhuma senha real faz parte do repositório ou dos artefatos de release.

Hash e verificação Argon2 compartilham limite de duas operações concorrentes por
processo. Isso limita a memória simultânea do algoritmo sem enfraquecer seus parâmetros.
Cada processo adicional requer seu próprio orçamento de memória.

A recaptura pública mantém recusa de consentimento e opt-out existentes. Se e-mail
e telefone correspondem a dois contatos, a API retorna 409 genérico sem escolher uma
identidade. A criação automática de oportunidade e tarefa permanece idempotente na
recaptura. Notas de contato ainda têm limite de 20.000 caracteres; histórico extenso
precisa de um modelo próprio de interações antes de expandir esse uso.
