# ADR-002 · CRM é a camada de restrição; OpenClaw é a camada de intenção

- **Status:** aceito · 2026-09-27
- **Decisores:** Walfredo Neto (CEO) · proposto pelo Palantyr v5

## Contexto
O Fattech-CRM já implementa o portão de agente (E1, E2, E4) com modo, teto, aprovação, recusa gravada e trilha selada.

## Decisão
Todo efeito de agente no negócio passa por /api/v1/agent/*. O OpenClaw não ganha motor de automação próprio, não acessa o banco, não usa rotas comuns (security.py já recusa a chave de agente fora do portão).

## Consequências
Um agente manipulado só consegue o que o modo, o escopo, o teto e a cadeia de aprovação permitem. Recusa é resultado, não erro.

## Alternativa descartada
Postgres somente-leitura para o agente (proposta anterior): retirada — contornaria RLS por organização e criaria segundo caminho de dado.
